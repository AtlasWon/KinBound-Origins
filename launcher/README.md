# The KinBound launcher

A small Electron shell around the game. It shows the installed version, checks
GitHub for a newer one, and starts the game in its own pixel-perfect window.

```
launcher/
  main.cjs      Electron main process: windows, the game protocol, IPC
  preload.cjs   the only bridge the launcher UI gets to the main process
  updater.cjs   GitHub release checking, downloading and installing
  config.json   which repository to check for updates
  icon.png      generated by  npm run icon
  ui/           the launcher page: index.html, style.css, app.js, hero.js
```

---

## Running it

| Command | What it does |
|---|---|
| `npm run launcher` | Compile, then open the launcher from source |
| `npm run dist` | Build `dist/KinBound-Setup-<version>.exe` (no publishing) |
| `npm run release` | Build **and** publish the release to GitHub |
| `npm run release -- --dry-run` | Full release build, published nowhere |
| `npm run icon` | Regenerate `launcher/icon.png` |
| `KINBOUND_SMOKE=1 npx electron .` | Render every screen, capture, quit |

## Two things worth knowing before you change anything

**The game is served from `kinbound://game`, not from a local web server.**
Saves live in `localStorage`, which is keyed by origin. A throwaway HTTP server
on a random port would hand the game a different origin on every launch and
silently wipe every save. The custom scheme gives one stable origin for the
life of the install. If you ever swap it for a port, pin the port.

**The launcher and the game update together, as one package.** A release
contains the Electron shell *and* the current `build/js`, `data` and
`index.html`. Splitting them would let somebody end up running new game data on
an old launcher, which is the exact failure this feature exists to prevent.

## Turning updates on

Updates are off until you point the launcher at a repository. Until then it
says "Update checks are not set up yet" and **Play still works normally** — an
unconfigured or offline update check must never stand between a player and
their game.

### 1. Make the repository

```bash
git add -A
git commit -m "KinBound"
```

The repository is <https://github.com/AtlasWon/KinBound-Origins>:

```bash
git remote add origin https://github.com/AtlasWon/KinBound-Origins.git
git branch -M main
git push -u origin main
```

### 2. Point the launcher at it

Edit `launcher/config.json`:

```json
{
  "github": { "owner": "AtlasWon", "repo": "KinBound-Origins" },
  "allowPrerelease": false
}
```

The launcher also reads `%APPDATA%\KinBound\update-config.json` and prefers it
when it exists, so an already-installed copy can be pointed somewhere new
without a rebuild.

### 3. Get a token

Create a personal access token at <https://github.com/settings/tokens> with the
`repo` scope (`public_repo` is enough for a public repository), then:

```powershell
$env:GH_TOKEN = "ghp_your_token_here"
```

### 4. Cut a release

Bump `version` in `package.json` — this is what the launcher compares against,
so **an update is only ever offered when this number goes up.** Then:

```bash
npm run release
```

That compiles, packages, and uploads a **draft** release. Open the repository's
Releases page and press *Publish release*. Until it is published, no launcher
will see it.

## What a player sees

| State | Launcher shows |
|---|---|
| Nothing configured | A note explaining how to switch updates on. Play works. |
| Up to date | "Up to date" in the info column, no panel |
| Newer release found | "Update available", version, release notes, **Update** |
| Downloading | A progress bar; Play stays enabled |
| Downloaded | "Update ready to install", **Restart and install** |
| Offline or failed | The reason, and a **Try again** button |

Saves are stored per-user, outside the install directory, and are untouched by
an update.

## Why the build needs a workaround on Windows

`electron-builder` unpacks a code-signing bundle that contains macOS symlinks.
Creating symlinks on Windows needs either Developer Mode or an elevated shell,
so on a normal account the unpack fails and the build retries forever.

Nothing in that bundle is needed for an unsigned Windows build except
`rcedit.exe`, so the fix is to unpack it once by hand:

1. Let `npm run dist` fail once — it leaves the archive in
   `%LOCALAPPDATA%\electron-builder\Cache\winCodeSign\`.
2. Copy any of the partially-extracted numbered folders there to
   `winCodeSign-2.6.0` in the same directory.
3. Delete the numbered folders and run `npm run dist` again.

Turning on Windows Developer Mode fixes it permanently and is less fiddly if
you plan to build often.
